开始使用

快速上手

在本机启动 Agent 工作台并连接现有 Auto System Editor。Editor 仍可独立运行，Agent 介入仅在开发模式下开放。

准备环境

需要 Bun、Go、Claude Code CLI，以及本地可运行的 Editor 工程。Web、Go API 和 TypeScript Daemon 位于同一个 monorepo。

安装与启动

在 Agent 仓库根目录安装依赖并创建本地配置：

make install
cp config.local.mk.example config.local.mk

编辑 config.local.mk，将 EDITOR_PATH 配置为 Editor 工程绝对路径。需要打开特定页面时，可将完整页面 URL 配到 EDITOR_PAGE_URL。该配置可能含登录凭据，只保存在本机，不要提交或分享。

make start

启动后访问 http://dev.auto-system.ai-local.com:8080/。已运行的 Editor 会被复用；否则开发栈会依据 EDITOR_PATH 启动它。

开始对话

  1. 进入 Editor 开发模式普通独立 Editor 的编辑和保存不依赖 Agent 工作台。
  2. 等待 Workspace 同步Web 从 Editor 获取页面快照，Go API 建立或恢复对应工作区。
  3. 发送任务选择已有 Session 继续，或新建会话。Agent 提交的 Patch 仍需在 Editor 中审阅并保存。

当前是本地单用户开发版。开发模式开关不是服务端身份认证，不要将 API 或 Daemon 暴露到公网。

开始使用

核心概念

工作区、修订、会话、运行和运行时是不同对象，分别拥有不同的生命周期与恢复边界。

核心对象

对象含义主要归属
Editor自动化页面编辑与保存界面，是页面内容的权威来源。自动化平台
Workspace一个 Editor 页面在 Agent 系统中的稳定工作空间。Go API
RevisionWorkspace 当前保存的 Editor 快照版本；各 Session 共用。Go API 保存，快照来自 Editor
Session可持续的 Claude 对话上下文；一个 Workspace 可有多个。Claude 本地记录，Go 保存最近绑定
Run一次用户触发的 Agent 执行，可续接某个 Session。Go 记录，Daemon 执行
Daemon本机服务，启动、取消和监控 Agent Runtime。TypeScript 服务
Runtime一次实际的 Claude Agent SDK 执行，不等同于长期会话。Daemon

对象关系

一个 Editor 页面对应一个 Workspace；一个 Workspace 只有一个当前 Revision，但可拥有多个 Session。用户选择 Session 后发起 Run，Daemon 为 Run 启动 Runtime，Runtime 通过 Claude Agent SDK 创建或续接会话。

记忆方法：Workspace 是容器，Revision 是当前快照，Session 是对话上下文，Run 是单次执行，Runtime 是执行进程。

开始使用

工作方式

Web 负责交互，Go API 负责工作区与运行记录，Daemon 负责本机执行。Editor 掌握页面的最终保存状态。

一次运行的完整链路

  1. Editor 提供快照开发模式下，Editor 将工作区标识和页面数据交给 Web。
  2. Web 请求 Go API请求携带 Workspace、Revision、Session 选择和用户消息。
  3. Go 准备工作目录保存 Revision，并将当前快照物化为只读文件。
  4. Daemon 启动 Claude RuntimeGo 将 Run 与 Session ID 交给 Daemon，由 SDK 执行 Agent。
  5. SSE 返回过程和结果事件经 Daemon、Go API 和 Web 实时传递。
  6. Editor 确认 Patch用户审阅并保存后，Go 确认新 Revision，工具调用才成功返回。

数据与执行边界

组件负责不负责
WebEditor 桥接、聊天、Session 选择、SSE 和人工审批。不作为 Workspace / Revision 权威存储。
Go APIWorkspace、Revision、Session 绑定、Run 和 FollowUp 记录。不执行模型请求。
DaemonRuntime 生命周期、事件转发和受限工具。不长期保存 Run 与事件历史。
Editor页面编辑、Patch 审阅、保存和最终页面状态。不管理 Agent Session 或 Runtime 生命周期。

Go 运行记录与 Claude Session 上下文是两类数据。Daemon 重启会中断活动 Runtime，但已保存的 Session 可供新 Run 尝试续接。

文档/工作区

工作区

工作区

Workspace 把一个 Editor 页面与 Agent 的稳定工作目录关联起来。Session 可以切换，当前 Editor Revision 只有一份。

页面与修订

一个 Editor 页面对应一个 Workspace。Editor 是页面数据来源；Go API 为已确认快照建立 Revision 并维护当前 HEAD。所有 Agent Session 共用这个 HEAD。

同步以 Editor 业务状态为准，并通过稳定哈希避免无意义的新 Revision。Editor 保存后，Go 更新工作区快照；多次保存可以在下一次真实运行时合并成当前差异，而不是每次保存都触发模型调用。

Agent 文件空间

Agent 根目录保持稳定。Editor 文件以只读快照形式位于 workspace/current/；CURRENT_WORKSPACE.md 描述当前版本和变更概况。Notes、Memory 与 Claude 运行状态在快照目录之外。

Agent 通过受限的 deliver_patch 将允许范围内的 JSON Patch 交给 Editor。草稿目录中的普通文件变化不会自动应用到页面。

内容权威

Editor 保存后的页面状态是权威内容。Patch 只是提案；只有 Editor 应用并保存、Go 确认新 Revision 后，修改才算交付。

工作区

成员与权限

当前版本面向本机开发者，不包含团队成员、角色或多租户权限系统。

当前边界

开发模式用于控制 Agent 工作台入口，不等同于用户身份认证或服务端授权。当前没有成员邀请、Workspace 角色、跨用户数据隔离或组织配额。

自动化平台的 JWT 服务于 Editor 的业务访问。本地 Agent API 尚未接入完整服务端身份校验，也不把 JWT 当作多租户授权机制。

共享服务前需要补齐

  • 服务端身份认证与 Workspace 级授权。
  • 用户、组织和 Workspace 的归属关系及数据隔离。
  • Runtime 凭据隔离、工具授权、资源配额和审计。
  • 多副本需要的共享持久化、幂等与分布式调度。

不要把当前本地服务直接作为多人生产服务部署。

文档/智能体

智能体

智能体

当前默认使用 Claude Agent SDK。Agent 身份、工具边界和 Session 续接由本机 Daemon 管理；Web 不直接连接模型服务。

默认：Claude Agent

Daemon 通过 Claude Agent SDK 的 query 执行模型交互。新对话创建 Claude Session；继续对话时，Go API 提供保存的 Session ID，Daemon 用它请求续接。

系统指令将 Agent 定义为自动化编辑 Agent：理解 Editor 导出的 ai-meta 和 Vue 工作区，按目标生成可验证的 Patch，并经 Editor 人工确认交付。它不是通用系统管理员，不能绕过 Editor 审核发布页面。

模型与工具

模型服务使用本机明确配置的 Anthropic API 风格凭据。当前工具包含只读文件检索、操作系统沙箱内 Bash，以及由 Daemon 提供的 deliver_patch、ask_user 等工作台工具。本机其他插件与工具配置不会自动继承。

后续方向：不同 Runtime

未来可在 Runtime 接口边界增加不同 Agent SDK 或 CLI Runtime。当前已实现链路仍是 Claude Agent SDK；Provider、模型和 Runtime 是不同层次，切换模型服务不意味着已经支持其他 Runtime。

Session ID 属于具体 Runtime 的会话机制。不同 Runtime 间不能假定 ID 可迁移，跨 Runtime 需要显式上下文交接设计。

文档/智能体

智能体

Skills / MCP

当前提供项目内置 Agent 指令与 Runtime Tools，不会自动继承开发者本机的全部 Skill 或 MCP 配置。

当前内置能力

Daemon 随运行注入自动化编辑 Agent 的身份、Patch 边界及依赖安装与验证要求。Daemon 管理的 MCP 工具包括向 Editor 提交 Patch、向用户提问等工作台能力。

工具请求经 Go API 和 Web 传递。Patch 需由用户在 Editor 审阅和保存，服务端确认新 Revision 后才向 Agent 返回成功。

不会自动继承本机配置

用户全局 Skill、Claude 插件和 .mcp.json 不会因本项目启动 Runtime 而自动挂载，以免无意继承宿主权限、凭据或执行范围。独立启动的 MCP Server 也需要单独的沙箱边界。

后续方向：动态加载

后续可建设按 Workspace 授权的能力目录，支持动态加载外部 Skill、CLI MCP，以及经审核接入的 SSE MCP Client / Server。每种能力都应明确来源、工具权限、网络访问、凭据范围和交付范围，再由用户或管理员显式授权。

动态 Skill 加载、通用 MCP 目录和 SSE MCP 接入目前均属规划，不是已交付能力。

文档/运行时与执行

运行时与执行

运行

Run 表示一次执行，不是长期会话。一个 Workspace 可通过多个 Session 开展不同对话，刷新后仍能回到对应 Session 查看和继续。

发起与恢复

用户发送消息后，Web 请求 Go API 创建 Run。可以继续最近 Session、切换历史 Session 或新建对话。Go 保存 Workspace 与 Session 绑定及运行历史；对话正文从 Claude 本地 Session 记录重建。

运行状态、文本增量、工具请求和最终结果通过 SSE 推送。刷新页面后，Web 恢复 Session、消息和未完成工具请求，再订阅活动 Run。

FollowUp、Steering 与取消

运行期间的新消息默认进入 FollowUp；用户明确选择引导时可作为 Steering 发送给活动 Runtime。消息由 Go API 记录并按运行状态处理。取消动作请求 Daemon 停止 Runtime，并更新 Run 终态。

工具结果与交付

如果 Agent 请求 deliver_patch，Editor 审阅并保存后，Web 将确认过的 Revision 回传。Go 校验 Revision 后，工具结果才返回 Daemon。送达状态不确定时会保留记录供核对，避免静默重复执行。

Run 完成只说明这一轮执行结束；用户仍可在同一 Session 中继续对话。

文档/运行时与执行

运行时与执行

守护进程与运行时

本地 Daemon 是 Go API 与 Agent Runtime 之间的执行桥梁。它管理执行进程和工具交互，但不拥有长期 Workspace 或 Session 记录。

Daemon 职责

TypeScript Daemon 监听本机回环地址，接收 Go API 的 Run 请求，检查工作区路径，启动 Claude Agent SDK Runtime，并把 SSE 事件、工具请求和终态返回给 Go API。它也负责取消执行、限制并发及托管 Runtime Tools。

浏览器经 Web BFF 与 Go API 通信，不直接访问 Daemon 内部接口。

稳定工作目录

每个 Workspace 有稳定的 Agent 根目录。Editor 快照以只读形式位于 workspace/current/；Notes、Memory 和 Claude 运行时状态各自位于快照之外。更新 Revision 不需要更换 cwd。

Bash 在操作系统沙箱中执行。SDK 直接的 Write / Edit 工具不开放；Editor 变更必须通过范围受限的 Patch 和人工审阅完成。

进程与恢复边界

状态Daemon 重启后说明
活动 Runtime不恢复原 Run 中断，需要新 Run。
内存事件缓冲不恢复Daemon 进程内的事件重放消失。
Go Workspace / Session 绑定保留由本地 Go Store 持久化。
Claude Session 文件保留新 Runtime 可尝试续接 Session。
Editor Revision保留由 Go API 的本地工作区存储管理。

Session 可恢复不代表 Run 可恢复：新 Runtime 能继续对话上下文，但不会自动恢复旧子进程、外部副作用或不确定的工具调用。

部署边界

当前系统面向可信任的本地单用户开发。未来可以将 API 与 Daemon 放在服务器，为工作区提供隔离执行环境；此前还需补齐身份认证、共享持久化、分布式调度与幂等、配额、密钥隔离和沙箱网络策略。

本地 Workspace + Runtime 与云端 Pod 只是部署形态上的类比，不代表当前已经具备 Pod 的隔离、弹性或故障恢复语义。
