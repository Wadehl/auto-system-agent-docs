系统架构

Auto System Agent 为现有自动化 Editor 提供独立的 Agent 工作台。它把对话与协调留在 Web / Go API，把 Claude Runtime 放在本机 Daemon 中运行；Editor 仍是页面内容与最终保存状态的权威来源。

01 · 定位

为 Editor 增加 Agent 工作台，不改造原自动化后端

Editor 仍由现有自动化平台启动、编辑和保存页面。Auto System Agent 在独立仓库中提供 Vue Web、Go Agent API 与 TypeScript Claude Daemon。两套系统通过工作台桥接契约交换快照、保存确认和 Patch 审阅结果。

浏览器只访问 Web 同源 API。Web BFF 做请求边界与转发；Go API 负责权威状态；Daemon 负责启动本机 Claude Agent SDK。浏览器不直接连接 Daemon。

02 · 组件边界

职责分开，状态有唯一归属

组件负责什么明确不负责什么
Vue WebEditor 桥接、聊天与 Session 选择、SSE 展示、FollowUp 队列、人工工具确认。不拥有权威 revision / Session ID；不直接调用 Daemon。
Web BFF提供同源 /api，执行 Origin、方法、路由与 CSRF 检查并流式转发。不持久化 Workspace、Session 或 Run。
Go Agent API维护 Workspace、不可变 Revision、Session 绑定、Run 历史、FollowUp 与工具决定；向 Agent 根目录物化快照。不启动 Claude CLI，也不保存完整对话上下文。
Claude Daemon校验本地允许路径、限制并发、启动 / 取消 SDK Run、暴露 Runtime 工具并转发事件。不充当长期 Session Store；活动进程和事件缓冲在重启后丢失。
Claude Agent SDK通过一次 query() 执行模型交互；给定 Session ID 时续接对话。不拥有 Editor revision；草稿文件不会自动成为 Editor 修改。
现有 Editor提供页面权威快照；审阅 Agent Patch；保存批准后的页面内容。不管理 Agent Session、Daemon 生命周期或 Go 运行队列。

03 · 对象模型

Workspace、Session、Run 与 Runtime 不是同一个东西

一个 Editor 页面对应一个稳定 Workspace。多个 Agent Session 可以围绕同一个 Workspace 继续或切换聊天，但当前 Editor 内容只有一个 revision HEAD。

对象语义当前保存位置
Workspace一个 Editor 页面在 Agent 工作台中的稳定身份。Go 本地 Store；一个当前 HEAD。
RevisionEditor 某一时刻的完整不可变快照；更新时按 baseRevision 做比较并交换。Go 本地快照 Store。
Agent Session可续接的一段 Claude 对话；同一 Session 可以跨多个 Run。Session ID 绑定由 Go 保存；Claude 上下文文件位于独立 session-state。
Run一次具体的模型执行，不等同于 Session 或 Daemon 进程。Go 保存提示、输出、终态与工具交互；Daemon 活动态只在内存。
FollowUpRun 活动期间用户排队的下一条文本 / 图片消息。Go 持久化消息与送达决定，终态后按顺序派发。
Runtime Tool RequestAgent 暂停并等待 Editor / 用户确认的工具请求。Go 持久化待处理决定，Web 刷新后可恢复展示。

04 · 执行路径

一次 Run 如何从浏览器走到模型服务

  1. Editor 建立工作区上下文开发模式下，Editor 通过受信任的 MessagePort 向 Web 传递 workspace 标识与当前快照。
  2. Web 经 BFF 发起 Run请求带上当前 Workspace、baseRevision、选中的 Session 或新建 Session 意图和用户输入。
  3. Go 校验并准备稳定 Agent 根目录API 校验 revision，将 Editor 文件以只读快照物化到 workspace/current/，准备本次 Run 输入。
  4. Daemon 启动 Claude SDK queryGo 将 Run 与 Session ID 交给 Daemon；Daemon 启动隔离的 Claude Runtime，必要时用 Session ID 续接上下文。
  5. SSE 回传过程与终态Daemon → Go → BFF → Web 转发状态、文本增量、工具请求和最终结果。Web 不轮询 Run。
  6. 服务端同时记录运行状态Go 独立订阅事件并持久化 Run 状态、Session 绑定与消息决定；关闭浏览器不会阻止这条记录路径。
SSE 断线后可携带 Last-Event-ID 重连。Daemon 的事件重放仅存在于当前进程；Daemon 重启不等于原 Run 继续执行。

05 · Editor 数据与补丁

快照更新不改变 Agent 的工作目录

Go 为每个 Workspace 保持稳定的 Agent 根目录。每份 Editor 快照生成不可变 Revision，再原子更新 workspace/current/。CURRENT_WORKSPACE.md 描述当前版本与变化路径；Notes.md、Memory/ 等记忆文件留在快照目录之外。因此更新快照不会替换 Runtime 的 cwd。

Editor → Agent

人工保存立即创建 Revision，但不自动触发模型请求。下一次真实用户 Run 才将所选 Session 上次基线到当前 HEAD 的合并差异提供给 Agent。

Agent → Editor

Agent 通过 deliver_patch 提交限定范围的 JSON Patch。Editor 审阅、应用并保存；Go 确认新 Revision 后，工具结果才返回 Runtime。

Agent 在 Bash 草稿目录中的其他文件改动不会自动发布到 Editor。只有经 Editor 明确确认并保存的 Patch 才会成为新快照。

06 · 会话与恢复

刷新可以恢复 Session，不代表恢复被杀掉的 Runtime

Web 刷新后向 Go 恢复 Session 列表、选中的 Session 消息、Workspace 的 Run 历史与未完成工具请求，并为活动 Run 恢复 SSE 订阅。Session 正文以 Claude 本地记录为依据；Run 历史描述一次执行与其工具交互，二者互补。

待处理的 Patch 或 ask_user 决定由 Go 留存，页面刷新后可以重新展示，不要求 Agent 重复调用工具。Daemon 重启会中止活动 Runtime 与其内存事件缓冲；保存的 Session ID 和 Claude 本地 Session 文件可供新的 Run 续接，但不会重建旧 Run 的现场。

07 · 安全与扩展

本地开发边界，不是多人生产认证

本机信任边界

Go API 与 Daemon 绑定回环地址；Web BFF 限制来源、方法和路由。开发模式不是服务端身份认证。

文件与命令边界

Daemon 校验允许路径，SDK 的 Bash 在操作系统沙箱内运行；快照只读，SDK Write / Edit 不开放。

并发边界

Go 文件 Store 的锁只覆盖单进程；Daemon 按 Workspace 串行执行并限制活动与排队数量。

部署到多人或 Pod 前仍需补齐

共享持久化 Store、跨副本幂等与任务调度、租户隔离、身份认证、队列与配额、凭据和沙箱网络隔离都尚未由当前本地实现提供。后续可在 Runtime 边界评估内部 SKILL、CLI MCP、SSE MCP 与外部 Skill，但必须逐项授权工具能力和访问范围；不会默认继承本机全部配置。

08 · 设计参考

借鉴 Multica 的对象分层，不复制其云端协作模型

Multica 文档把工作区、任务、Agent、Runtime 与单次 Run 分开描述：平台侧管理协作记录与状态，连接的执行环境调用本地工具。Auto System Agent 借鉴这种“协调层与执行层分离”及对象边界，用于单个 Editor 工作区。

两者业务对象并不完全对应。本项目当前没有 Multica 的团队任务、成员权限、小队或云端调度；Go API 也不是多人协调服务。未来把 Daemon 放入服务器 Pod，还需要重新明确 Revision、Session 与执行状态的持久化和调度边界。
